1 Dasar-dasar: VPS, SSH, dan istilahnya

Kenapa tidak bisa pakai cPanel / shared hosting biasa?

cPanel adalah panel untuk shared hosting — hosting untuk situs "pasif" (PHP, WordPress, halaman statis) yang server webnya dikelola host. Aplikasi Anda bukan itu: ia adalah server Node.js yang berjalan terus-menerus (Next.js di port 3000) plus bot Telegram yang juga berjalan di latar belakang. Shared hosting tidak mengizinkan proses background jangka panjang, tidak ada terminal/SSH untuk build, versi Node-nya tua, dan rahasia server Anda tidak aman dibangun di mesin orang lain.

Kesimpulan: aplikasi ini butuh VPS — komputer sewaan penuh milik Anda. Di sanalah semua metode di panduan ini berjalan.

Istilah singkat (lengkap di glosarium bab 13)

  • VPS — komputer sewaan yang menyala 24 jam, diisi aplikasi Anda.
  • SSH — "pintu masuk aman" ke VPS lewat terminal; cara Anda memberi perintah ke server.
  • Terminal / PowerShell — jendela tempat mengetik perintah (bawaan Windows).
  • Node.js — "mesin" yang menjalankan aplikasi Anda (versi 20).
  • npm — pengelola paket; perintah npm install & npm run build mengolah aplikasi.
  • Port 3000 — "pintu" tempat aplikasi web mendengar. Nginx nanti meneruskan dari port 80/443 ke 3000.
  • Nginx — web server publik yang menghubungkan domain → aplikasi, dan mengurus HTTPS.
  • HTTPS / SSL — kunci gembok di browser; wajib untuk situs berbayar.
  • Swap — sebagian disk dipinjam jadi "RAM darurat" agar proses build tidak mati.

2.3 Buat VPS & catat info penting

  1. Daftar akun di penyedia pilihan → buat server baru (droplet / cloud server).
  2. Pilih OS: Ubuntu 24.04 LTS (atau 22.04 LTS).
  3. Pilih paket sesuai spek di atas.
  4. Autentikasi: kalau ada pilihan SSH key dan Anda belum paham, pilih password dulu. Simpan password-nya.
  5. Setelah dibuat, catat IP address, misal 203.0.113.10.
  6. Domain: Anda juga butuh nama domain (mis. ytc-web.com) supaya bisa HTTPS & link unduhan di email berfungsi. Beli di registrar mana saja, lalu di panel penyedia, arahkan DNS domain ke IP VPS (type A record → IP). Jika belum punya domain, Anda tetap bisa ikuti panduan ini sampai uji via IP (http://IP:3000), lalu pasang domain belakangan.

2.4 Masuk VPS pertama kali (SSH)

Buka PowerShell di Windows, ketik:

Di komputer Andassh root@203.0.113.10

Ganti 203.0.113.10 dengan IP Anda. Ketika diminta password, ketik password VPS. (Huruf tidak muncul di layar saat mengetik password — itu normal.)

Kalau gagal: pastikan VPS mengizinkan login password (panel penyedia biasanya punya opsi "Enable password auth"). Kalau tetap gagal, hubungi dukungan penyedia.

Begitu berhasil, Anda akan melihat baris perintah seperti root@ubuntu:~#. Dari sini semua perintah dijalankan. Panduan ini selalu menandai Di komputer Anda vs Di VPS — ini yang paling sering membingungkan pemula.

3 Setup awal server (sekali saja)

Semua perintah di bab ini dijalankan di dalam VPS (setelah SSH masuk).

3.1 Update sistem
Di VPSapt update
apt upgrade -y
Kenapa? Ini memperbarui keamanan sistem. Server yang up-to-date jauh lebih sulit ditembus.
3.2 Buat pengguna non-root (disarankan)

Bekerja sebagai root itu berisiko — satu kesalahan bisa merusak sistem. Buat pengguna biasa yang punya izin admin:

Di VPSadduser deploy
usermod -aG sudo deploy

(Buat passwordnya, isi saja yang ditanyakan dengan Enter.) Mulai sekarang masuk SSH sebagai deploy, bukan root:

Di komputer Andaexit
ssh deploy@203.0.113.10
Tips: untuk panduan ini, Anda bisa tetap lanjut sebagai deploy. Kalau suatu saat perlu izin root, pakai sudo <perintah>.
3.3 Pasang Node.js 20 (via nvm)

nvm (Node Version Manager) memudahkan ganti versi Node. Aplikasi ini butuh Node 20.

Di VPScurl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 20

Cek berhasil:

Di VPSnode -v
npm -v

Harus keluar v20.x.x dan 10.x.x (atau lebih baru).

3.4 Pasang Git
Di VPSsudo apt install -y git
Kenapa? Dipakai untuk menyalin kode dari repo Anda (cara paling rapi untuk mengirim aplikasi).
3.5 Buat swap 2 GB (pengaman RAM)

Khusus kalau RAM 1 GB, ini wajib supaya proses build tidak mati. Kalau RAM 2 GB, tetap bagus dipasang.

Di VPSsudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
Kenapa? Swap = pinjam sedikit disk sebagai "RAM darurat". Build Next.js kadang butuh sampai ±2 GB.

4 Siapkan aplikasi (wajib untuk semua metode)

4.1 Kirim kode aplikasi ke VPS

Ada 2 cara. Disarankan: via Git (lebih rapi untuk update di masa depan).

  • Cara A (disarankan) — Git: upload folder C:\ytc-web Anda ke GitHub/GitLab sebagai repo privat (jangan publik — ada file & kode rahasia). Lalu di VPS: 
    Di VPSmkdir -p ~/apps
cd ~/apps
git clone https://github.com/NAMA-ANDA/NAMA-REPO.git ytc-web
cd ytc-web
  • Cara B (tanpa Git) — SCP/WinSCP: salin isi folder dari komputer Anda ke VPS. Buka dulu folder tujuannya: 
    Di VPSmkdir -p ~/apps/ytc-web
cd ~/apps/ytc-web
    Lalu dari PowerShell komputer Anda: 
    Di komputer Andascp -r C:\ytc-web\* deploy@203.0.113.10:~/apps/ytc-web/

    (Alternatif tanpa mengetik perintah: gunakan aplikasi gratis WinSCP — tampilannya seperti Windows Explorer, drag & drop.)

4.2 Buat file rahasia .env.local

Buka file .env.local di komputer Anda, salin semua isinya. Di VPS, buat file dengan isi yang sama:

Di VPSnano .env.local

Tempel (di nano: klik kanan untuk tempel) → simpan Ctrl+O → Enter → keluar Ctrl+X.

WAJIB diubah sebelum go-live:
  • NEXT_PUBLIC_APP_URL=https://DOMAIN-ANDA — ganti dengan domain final Anda (dipakai untuk link di email & keamanan). Ubah SEBELUM build.
  • ADMIN_PASSWORD & ADMIN_GATE_PASSWORD — password kuat & berbeda.
  • ADMIN_SESSION_SECRET & CRON_SECRET & TELEGRAM_WEBHOOK_SECRET — string acak panjang.
  • WEBHOOK_BASE_URL=https://DOMAIN-ANDA — ganti dari localhost.
Kenapa satu file untuk semua? Aplikasi web (Next.js) dan bot Telegram sama-sama membaca .env.local. Satu file = semua kebaca.
Keamanan: jangan pernah commit .env.local ke Git, dan jangan pernah upload ke repo publik. Isinya adalah kunci rumah Anda.
4.3 Jalankan migration database di Supabase (manual)

Beberapa fitur baru butuh kolom/tabel tambahan. Buka Supabase Dashboard → SQL Editor → New Query, lalu jalankan file-file SQL berikut satu per satu (dari folder C:\ytc-web\supabase\migrations\):

  • secure-download.sql
  • 2026_permanent_2paket.sql
  • 2026_cashback_schema_fix.sql
  • 2026_cashback_code_email.sql
  • 2026_qris_static_payment.sql (yang terbaru)

Selanjutnya di Dashboard → Storage: pilih bucket cashback-proofs → ubah menjadi Private (jangan Public).

Kenapa? Supabase adalah "database & penyimpanan" Anda (di luar VPS, sudah gratis). Migration menambah fitur; bucket private melindungi bukti klaim pelanggan.

★ JALUR UTAMA — PM2 (disarankan)

PM2 = "penjaga aplikasi". Ia menjalankan aplikasi di latar belakang, menghidupkan lagi otomatis kalau crash, dan menyalakan lagi setelah reboot. Tanpa PM2, aplikasi mati begitu Anda keluar dari SSH. Ini standar industri untuk aplikasi Node.js.

5.1 Pasang PM2
Di VPSsudo npm install -g pm2
5.2 Install & build aplikasi

Masuk ke folder aplikasi lalu jalankan:

Di VPScd ~/apps/ytc-web
npm ci
npm run build
Build berhasil bila muncul ✓ Compiled successfully dan daftar route. Kalau tiba-tiba mati / "heap out of memory" → RAM kurang; pastikan swap aktif (lihat bab 3.5).
5.3 Uji manual dulu (opsional)
Di VPSnpm run start

Buka http://203.0.113.10:3000 di browser. Muncul beranda → berhasil. Hentikan dengan Ctrl+C.

5.4 Buat file konfigurasi PM2

File ini memberitahu PM2 cara menjalankan dua proses: server web + bot Telegram. Buat di folder aplikasi:

Di VPSnano ecosystem.config.cjs

Isi dengan:

Isi filemodule.exports = {
  apps: [
    {
      name: "ytc-web",
      cwd: __dirname,
      script: "npm",
      args: "run start",
      env: { NODE_ENV: "production", PORT: 3000 },
      max_memory_restart: "512M",
    },
    {
      name: "ytc-telegram",
      cwd: __dirname,
      script: "node",
      args: "scripts/telegram-poll.mjs",
      max_memory_restart: "256M",
    },
  ],
};

Simpan: Ctrl+O → Enter → Ctrl+X.

Pindah dari Vercel ke VPS? Di Vercel bot biasanya memakai webhook (Telegram menelpon URL situs). Di VPS ganti ke polling dengan urutan wajib:
  1. Sebelum mematikan Vercel, hapus webhook sekali: curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook"
  2. Di VPS, proses ytc-telegram (polling scripts/telegram-poll.mjs) otomatis mengambil alih — pm2 start ecosystem.config.cjs sudah mencakupnya.
  3. Pakai .env.local dengan nilai sama, hanya NEXT_PUBLIC_APP_URL diganti domain VPS sebelum build.
  4. Jangan aktifkan webhook dan polling bersamaan — salah satu pasti error.
5.5 Jalankan kedua proses
Di VPSpm2 start ecosystem.config.cjs
pm2 status

Keduanya harus online. Lihat log kalau ada error:

Di VPSpm2 logs ytc-web
pm2 logs ytc-telegram
5.6 Pastikan hidup setelah reboot
Di VPSpm2 save
pm2 startup

pm2 startup akan mencetak satu baris perintah — salin & jalankan baris itu (sekali saja). Ini membuat PM2 otomatis hidup setelah server reboot.

5.7 Nginx: jembatan dari internet ke aplikasi

Tanpa Nginx, orang harus akses via http://IP:3000 (tanpa kunci gembok). Nginx menerima permintaan di port 80/443 lalu meneruskannya ke aplikasi di port 3000.

Di VPSsudo apt install -y nginx

Buat konfigurasi domain:

Di VPSsudo nano /etc/nginx/sites-available/ytc-web

Isi (ganti ytc-web.com dengan domain Anda):

Isi fileserver {
    listen 80;
    server_name ytc-web.com www.ytc-web.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

Simpan, lalu aktifkan:

Di VPSsudo ln -s /etc/nginx/sites-available/ytc-web /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
Kenapa baris X-Real-IP penting? Aplikasi Anda memakai alamat IP untuk keamanan (rate limit). Nginx perlu menyampaikan IP asli pengunjung, bukan IP server.
5.8 HTTPS gratis (Let's Encrypt)

Kunci gembok browser. Diperlukan sebelum domain dipakai publik.

Di VPSsudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ytc-web.com -d www.ytc-web.com

Ikuti pertanyaannya (email, setujui syarat). Selesai → kunjungi https://ytc-web.com, harus ada kunci gembok hijau.

Kenapa wajib? Tanpa HTTPS browser bisa memblokir beberapa fitur, dan data pelanggan (nama, email, WA) jadi rentan dibaca di perjalanan.
5.9 Firewall

Tutup semua pintu kecuali SSH (22), web (80/443):

Di VPSsudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
Jangan lupa izinkan SSH dulu sebelum ufw enable — kalau tidak, Anda terkunci keluar.

6 Metode A — aaPanel (GUI, mirip cPanel)

aaPanel memberi Anda dashboard web ber-GUI di atas VPS: buat file, atur domain, pasang SSL, dan kelola Node.js — semuanya dengan klik, tidak perlu hafal perintah terminal. Cocok kalau Anda benar-benar tidak nyaman mengetik perintah. Di balik layar, aaPanel memakai PM2 juga, jadi yang Anda pelajari di sini tetap berguna.

Catatan jujur: panel pihak ketiga menambah permukaan serangan & perlu di-update rutin. Untuk situs berbayar, jalur PM2 (bab 5) lebih disarankan. Pakai aaPanel kalau Anda lebih mengutamakan GUI.
6.1 Install aaPanel (di VPS, satu perintah)
Di VPSwget -O install.sh http://www.aapanel.com/script/install-ubuntu_6.0_en.sh
sudo bash install.sh

Di akhir install, panel mencetak: URL panel (mis. http://IP:8888/xxxxx), username, dan password. Catat ketiganya.

Penting: instalasi aaPanel meminta pilih opsi "LNMP" saat bertanya komponen. Kamu bisa melewati/hentikan yang tidak perlu; yang benar-benar dipakai hanya Nginx dan Node.js.
6.2 Buka panel & nonaktifkan default agar aman

Buka URL panel di browser. Di Security, batasi akses panel: hanya izinkan IP Anda, dan ubah port panel 8888 ke angka lain. Aktifkan firewall panel juga.

6.3 Kirim kode aplikasi

Buka Files di aaPanel → buat folder /www/wwwroot/ytc-web → upload isi folder C:\ytc-web lewat tombol Upload (atau gunakan Git/Git clone jika panelnya mendukung). Buat juga file .env.local di folder itu dengan isi dari komputer Anda (lihat bab 4.2).

6.4 Build aplikasi (via Terminal bawaan aaPanel)

aaPanel punya menu Terminal. Jalankan:

Di aaPanel (Terminal)cd /www/wwwroot/ytc-web
npm ci
npm run build
6.5 Buat website + reverse proxy

Di Website → Add site: masukkan domain Anda (arahkan DNS domain ke IP VPS dulu), pilih PHP saja (tidak dipakai, aman). Setelah jadi, buka Settings → Reverse Proxy: target http://127.0.0.1:3000. Selesai → SSL → aktifkan Let's Encrypt (sekali klik).

6.6 Jalankan aplikasi via Node.js Manager

Di aaPanel cari App Store → Node.js Manager (install kalau belum ada). Di PM2 Manager: Add project → pilih /www/wwwroot/ytc-web, startup file npm dengan argumen run start, env NODE_ENV=production & PORT=3000. Add lagi satu proyek untuk bot: file node, argumen scripts/telegram-poll.mjs. Status keduanya harus "online".

6.7 Tes & go-live

Buka domain Anda (dengan HTTPS), ikuti alur tes di bab 5.10. Update aplikasi: upload kode baru → build lagi → restart PM2 di Node.js Manager.

7 Metode C — Systemd (bawaan Ubuntu)

Systemd adalah pengelola proses bawaan Ubuntu — tidak perlu menginstall apa pun. Fungsinya sama seperti PM2. File unit-nya sudah saya siapkan di folder deploy/ kode Anda: ytc-web.service (server web) dan ytc-telegram.service (bot Telegram).

Peringatan: pilih satu penjaga proses saja. Kalau sudah memakai PM2 (pm2 delete ytc-web & pm2 delete ytc-telegram dulu), baru gunakan systemd.
7.1 Sesuaikan path di file unit

File deploy/ytc-web.service & deploy/ytc-telegram.service menunjuk ke /home/deploy/apps/ytc-web dan user deploy. Pastikan folder aplikasi Anda di sana (bab 4.1).

7.2 Salin & aktifkan
Di VPSsudo cp deploy/ytc-web.service deploy/ytc-telegram.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ytc-web ytc-telegram

Cek status & log:

Di VPSsystemctl status ytc-web
journalctl -u ytc-web -n 50 --no-pager

Ulangi untuk ytc-telegram. Lanjutkan ke Nginx + HTTPS + firewall (bab 5.7–5.9), lalu tes (bab 5.10).

7.3 Perintah harian systemd

sudo systemctl restart ytc-web (mulai ulang) · sudo systemctl stop ytc-web (hentikan) · systemctl status ytc-web (lihat status) · sudo systemctl enable --now ytc-web (nyalakan saat boot).

8 Metode D — Docker (paling portabel)

Docker membungkus aplikasi + seluruh kebutuhannya ke dalam "container" yang identik di server mana pun. File Dockerfile, docker-compose.yml, dan .dockerignore sudah saya siapkan di kode Anda. docker-compose.yml menjalankan 2 service sekaligus: web (Next.js di port 3000) dan telegram (bot).

Peringatan: pakai satu cara saja — berhentikan PM2/systemd dulu sebelum menjalankan Docker.
8.1 Install Docker (sekali)
Di VPScurl -fsSL https://get.docker.com | sudo sh

8.2 Buat file .env untuk nilai build

Next.js menanamkan nilai NEXT_PUBLIC_* saat build. Buat file .env di folder aplikasi:

File .env.local (bab 4.2) juga tetap dibutuhkan — dipakai saat runtime.

8.4 Update & perintah harian

Catatan: kalau NEXT_PUBLIC_APP_URL berubah, harus di-build ulang (docker compose up -d --build) karena nilainya sudah tertanam.

9 Checklist go-live

Sebelum mempublikasikan, centang semua:

  • Domain mengarah ke IP VPS (DNS A record) & HTTPS aktif (kunci gembok).
  • NEXT_PUBLIC_APP_URL di .env.local sudah = domain final sebelum build terakhir.
  • Semua migration SQL sudah dijalankan di Supabase + bucket cashback-proofs Private.
  • Di /admin → Settings: promo diatur, harga sesuai, cashback sesuai.
  • Pembayaran QRIS: upload gambar QRIS GoPay, aktifkan toggle, cek instruksi tampil benar.
  • Alur beli diuji end-to-end sampai email invoice + link unduhan masuk (cek folder Spam!).
  • Telegram: notif order baru & klaim cashback masuk ke chat Anda; bot menjawab /help.
  • Admin login & gate password diuji, cookie sesi aman (httpOnly).
  • .env.local tidak ikut ter-commit; izin file rahasia ketat (bab 10).

10 Keamanan

Aplikasi sudah dibekali lapisan keamanan dari kode (rate limit, validasi input, verifikasi signature, signed URL untuk bukti klaim, audit log perubahan status, cookie admin ber-tanda tangan, dan lain-lain). Yang wajib Anda jaga dari sisi server:

  • File rahasia. Pastikan .env.local di VPS hanya bisa dibaca pemiliknya: 
    Di VPSchmod 600 ~/apps/ytc-web/.env.local
  • Jangan pernah commit .env.local ke Git, apalagi ke repo publik.
  • Firewall aktif (ufw / firewall aaPanel) — hanya port 22, 80, 443 yang terbuka.
  • Update rutin: sudo apt update && sudo apt upgrade berkala; kalau pakai aaPanel, update panelnya juga.
  • Backup: data utama ada di Supabase (aktifkan daily backup di dashboard). Untuk kode, Git repo Anda adalah backup-nya.
  • Password kuat & berbeda untuk SSH, admin panel, ADMIN_PASSWORD, ADMIN_GATE_PASSWORD.

11 Troubleshooting umum

GejalaSolusi & sebab
Build mati / "heap out of memory"RAM habis saat build. Aktifkan/naikkan swap (bab 3.5), atau naikkan paket VPS ke 2 GB.
Port 3000 sudah dipakai saat startAda proses lama. sudo lsof -i :3000 → sudo kill -9 <PID>, lalu start ulang.
Halaman 502 Bad Gateway (Nginx)App mati atau belum start. Cek pm2 status (atau docker compose ps) dan log; lalu sudo systemctl reload nginx.
Bot Telegram tidak meresponsCek token (TELEGRAM_BOT_TOKEN), pm2 logs ytc-telegram, pastikan internet VPS lancar. Pastikan hanya polling atau webhook yang aktif, tidak dua-duanya.
Modal QRIS tidak muncul saat beliToggle QRIS di /admin → Settings belum aktif, atau URL gambar QRIS kosong, atau migration 2026_qris_static_payment.sql belum dijalankan.
Email invoice tidak terkirimCek SMTP_* di .env.local, cek folder Spam pelanggan, dan lihat kolom "Status Email" order di /admin (Terkirim/Gagal).
Gambar bukti klaim tidak bisa dibuka adminBucket cashback-proofs harus Private; signed URL dibuat otomatis oleh server (isi ulang halaman admin).
Tidak bisa SSHIP benar? Firewall/panel penyedia mengizinkan port 22? "Enable password auth" aktif?

NginxWeb server yang menjadi pintu depan: domain → aplikasi, plus HTTPS.
HTTPS / SSL / Let's EncryptKunci gembok browser; Let's Encrypt adalah yang membuatnya gratis.
SystemdPengelola proses bawaan Ubuntu (alternatif PM2 tanpa install aplikasi).
Docker / containerMembungkus aplikasi + kebutuhannya jadi satu paket yang berjalan sama di server mana pun.
