1 Apa itu VPS?

VPS (Virtual Private Server) adalah "komputer sewaan" yang selalu menyala di pusat data. Aplikasi web Anda butuh komputer yang menyala 24 jam — itulah VPS. Anda bayar per bulan, dan server itu sepenuhnya milik Anda.

Analogi sederhana: website Anda seperti sebuah toko. Sebelumnya "tokonya" dititipkan di layanan Vercel. Dengan VPS, Anda menyewa toko sendiri (server) dan mengelolanya sendiri. Sedikit lebih banyak urusan, tapi lebih murah, lebih besar, dan Anda punya kendali penuh.

Yang Anda butuhkan sebelum mulai:

  • Kode aplikasi (sudah ada di folder C:\ytc-web).
  • Satu VPS (dibeli dari penyedia — langkah di bawah).
  • File konfigurasi rahasia (.env.local) — sudah Anda miliki.
  • Sebuah nama domain (mis. ytc-web.com) — disarankan, opsional.
Kabar baik: kode ini tidak bergantung pada Vercel. Semua bagian penting (database Supabase, penyimpanan file R2, email Gmail, notifikasi Telegram) berjalan di luar server, jadi tinggal "menjalankan" aplikasinya saja di VPS.

2 Spek VPS yang disarankan

Aplikasi ini ringan (Next.js + database di luar). Yang paling rawan justru proses build (menyusun aplikasi) yang butuh RAM cukup.

Komponen Minimum (cukup) Recommended (nyaman)
CPU 1 vCPU 2 vCPU
RAM 1 GB (+ swap 2 GB) 2 GB
Disk (SSD) 20 GB 40 GB
Bandwidth 1 TB / bulan (sangat cukup) ≥ 1 TB / bulan
OS Ubuntu 22.04 / 24.04 LTS Ubuntu 24.04 LTS

Penjelasan singkat tiap angka

  • RAM: proses npm run build butuh sekitar 1–2 GB. Kalau RAM 1 GB, wajib pasang swap (lihat bawah) supaya build tidak gagal/mati.
  • CPU & disk: runtime aplikasi ringan; 2 vCPU & SSD membuat build lebih cepat dan browsing lebih responsif.
  • Bandwidth: traffic Anda (1 jam → 10 klip, download installer) kecil. 1 TB/bulan jauh dari cukup kecuali aplikasi sangat viral.

Mengenai swap (cadangan RAM)

Swap = sebagian hard disk dipinjam sebagai "RAM tambahan darurat". Dipakai agar proses build tidak mati saat RAM penuh. Perintah membuat swap 2 GB: 

Di VPSsudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
Tips: pakai spek Recommended (2 GB RAM) kalau mau bebas khawatir. Selisih biaya biasanya cuma sekitar Rp30–50 ribu/bulan.

3 Persiapan: beli & akses VPS

3.1 Pilih penyedia VPS

Penyedia populer untuk Indonesia, diurutkan dari yang paling mudah:

PenyediaKeunggulanPerkiraan harga
idcloudhost / HostingerPusat data lokal, panduan Bahasa Indonesia, dukungan cepatRp70–150rb/bulan
DigitalOcean / VultrPaling populer, dokumentasi lengkap, droplet 1 klik$6–12/bulan
HetznerTermurah & handal (paling hemat)€4–8/bulan
Catatan harga: nominal di atas perkiraan pasar dan bisa berubah. Beli yang speknya mengikuti bagian #2.

3.2 Buat VPS / droplet

  1. Daftar akun di penyedia pilihan.
  2. Pilih OS: Ubuntu 24.04 LTS (atau 22.04 LTS).
  3. Pilih paket sesuai spek di atas.
  4. Saat diminta SSH key: jika belum paham, pilih password dulu (lebih mudah untuk pemula). Catat password-nya.
  5. Buat server. Catat IP address VPS, misal 203.0.113.10.

3.3 Apa itu SSH & cara masuk

SSH = pintu masuk aman ke komputer VPS lewat terminal. Anda mengetik perintah, dan VPS menjalankannya. Di Windows, gunakan PowerShell (aplikasi bawaan) — ketik perintah berikut: 

Di komputer Andassh root@203.0.113.10

(ganti 203.0.113.10 dengan IP VPS Anda). Jika diminta password, ketik password VPS tadi (huruf yang diketik tidak muncul di layar — itu normal).

Tips kalau SSH gagal: pastikan VPS mengizinkan login password (di panel penyedia biasanya ada opsi "Enable password auth"). Kalau tetap gagal, hubungi bantuan penyedia.

4 Setup awal server

Semua perintah di bagian ini dijalankan di dalam VPS (setelah SSH masuk).

4.1 Perbarui sistem
Di VPSsudo apt update
sudo apt upgrade -y
4.2 Buat pengguna admin (bukan root)

Bekerja memakai akun biasa lebih aman daripada akun root.

Di VPSsudo adduser deploy
sudo usermod -aG sudo deploy
su - deploy
4.3 Install Node.js 20 (dibutuhkan aplikasi)
Di VPScurl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v
npm -v

Harus menampilkan versi (mis. v20.x.x dan 10.x.x).

4.4 Install Nginx, Certbot, dan PM2
Di VPSsudo apt-get install -y nginx
sudo apt-get install -y certbot python3-certbot-nginx
sudo npm install -g pm2

Penjelasan: Nginx = gerbang web yang meneruskan pengunjung ke aplikasi. Certbot = pemasang SSL (gembok HTTPS) otomatis. PM2 = penjaga yang memastikan aplikasi terus menyala (dibahas di #6).

4.5 Aktifkan firewall
Di VPSsudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable

Ini hanya mengizinkan akses SSH (port 22) dan web (80/443). Semua port lain tertutup.

4.6 Install Git (untuk mengunduh kode)
Di VPSsudo apt-get install -y git

5 Pasang aplikasi

5.1 Kirim kode aplikasi ke VPS

Ada 2 cara:

  • Cara A (disarankan): upload kode Anda ke GitHub (repo privat), lalu di VPS: 
    Di VPSmkdir -p ~/apps
cd ~/apps
git clone https://github.com/NAMA-ANDA/NAMA-REPO.git ytc-web
cd ytc-web
  • Cara B (tanpa GitHub): salin folder C:\ytc-web ke VPS memakai WinSCP (aplikasi gratis transfer file), atau perintah SCP dari komputer Anda: 
    Di komputer Andascp -r C:\ytc-web\* deploy@203.0.113.10:~/apps/ytc-web/
5.2 Buat file rahasia .env.local

Buat file .env.local di folder aplikasi di VPS — isinya sama dengan file .env.local di komputer Anda (jangan pernah dibagikan/di-upload ke repo publik!). Cara paling mudah: buka file itu di komputer Anda, salin semua isinya, lalu di VPS: 

Di VPSnano .env.local

Tempel isinya (di nano: klik kanan untuk tempel), simpan dengan Ctrl+O lalu Enter, keluar dengan Ctrl+X.

Wajib diubah sebelum go-live:
  • NEXT_PUBLIC_APP_URL=https://NAMA-DOMAIN-ANDA — ganti dengan domain Anda (dipakai untuk link di email & pengamanan browser).
  • ADMIN_PASSWORD & ADMIN_GATE_PASSWORD — pakai kata sandi kuat yang berbeda.
  • ADMIN_SESSION_SECRET — ganti dengan string acak panjang (contoh buat acak: openssl rand -hex 32).

Kenapa file namanya .env.local dan bukan .env.production? Karena dua proses di sini (aplikasi Next.js dan script bot Telegram) sama-sama membaca file itu. Next.js otomatis membacanya, dan script polling juga membacanya. Satu file, semua kebaca — paling sederhana.

5.3 Install & build
Di VPSnpm install
npm run build
Build berhasil bila di layar muncul ✓ Compiled successfully dan daftar route. Kalau tiba-tiba mati / heap out of memory → RAM kurang; pastikan swap aktif (lihat #2).
5.4 Uji jalan dulu (manual)
Di VPSnpm run start

Buka http://203.0.113.10:3000 di browser. Kalau muncul beranda YouTube Clipper → berhasil! Hentikan dengan Ctrl+C, lanjut ke langkah PM2.

6 PM2 — penjaga aplikasi

PM2 menjalankan aplikasi di latar belakang, lalu menghidupkannya lagi otomatis kalau crash, dan menyalakannya lagi setelah server reboot. Tanpa PM2, aplikasi mati begitu Anda keluar dari SSH.

6.1 Buat file konfigurasi PM2

Di folder aplikasi, buat file ecosystem.config.cjs:

Di VPSnano ecosystem.config.cjs

Isi dengan:

Isi filemodule.exports = {
  apps: [
    {
      name: "ytc-web",
      cwd: __dirname,
      script: "npm",
      args: "run start",
      env: { NODE_ENV: "production", PORT: 3000 },
      max_memory_restart: "512M",
    },
    {
      name: "ytc-telegram",
      cwd: __dirname,
      script: "node",
      args: "scripts/telegram-poll.mjs",
      max_memory_restart: "256M",
    },
  ],
};

Simpan: Ctrl+O → Enter → Ctrl+X.

6.2 Jalankan
Di VPSpm2 start ecosystem.config.cjs
pm2 status

Kedua aplikasi harus berstatus online. Lihat log (jika ada error) dengan:

Di VPSpm2 logs ytc-web
pm2 logs ytc-telegram
6.3 Pastikan hidup setelah reboot
Di VPSpm2 save
pm2 startup

pm2 startup akan memberi satu baris perintah — salin & jalankan baris itu (sekali saja).

Perintah harian yang berguna: pm2 status (lihat semua), pm2 logs (lihat log), pm2 restart ytc-web (mulai ulang), pm2 stop ytc-web (hentikan).
Tidak mau pakai PM2? Ada 2 alternatif yang sama-sama sudah saya siapkan di folder kode: Opsi A: Systemd (bawaan Ubuntu, paling sederhana) dan Opsi B: Docker. Pilih satu saja — jangan menjalankan PM2 dan systemd/Docker untuk proses yang sama secara bersamaan.

A Opsi A — Systemd (pengganti PM2)

Systemd adalah pengelola proses bawaan Ubuntu — jadi tidak perlu menginstall apa pun. Berfungsi sama seperti PM2: menjalankan aplikasi di latar belakang, menghidupkannya lagi kalau crash, dan menyalakannya lagi setelah reboot. Cocok kalau Anda tidak mau menambah aplikasi lain (PM2).

File unit-nya sudah disiapkan di folder deploy/ dalam kode Anda: ytc-web.service (server web) dan ytc-telegram.service (bot Telegram).

Peringatan: kalau Anda sudah menjalankan PM2 (pm2 delete ytc-web & pm2 delete ytc-telegram dulu), baru gunakan systemd — jangan keduanya sekaligus.
A.1 Salin file unit ke tempat systemd
Di VPSsudo cp deploy/ytc-web.service deploy/ytc-telegram.service /etc/systemd/system/

(Pastikan dulu jalur di dalam file sesuai lokasi kode Anda. Jika folder kode bukan /home/deploy/apps/ytc-web, edit dengan sudo nano /etc/systemd/system/ytc-web.service.)

A.2 Aktifkan & nyalakan
Di VPSsudo systemctl daemon-reload
sudo systemctl enable --now ytc-web ytc-telegram

Kode enable membuatnya menyala otomatis saat reboot; --now langsung menjalankannya sekarang.

A.3 Perintah sehari-hari
Di VPSsystemctl status ytc-web            # lihat status
sudo journalctl -u ytc-web -f       # lihat log (keluar: Ctrl+C)
sudo systemctl restart ytc-web      # mulai ulang
sudo systemctl stop ytc-web         # hentikan
sudo systemctl restart ytc-telegram # mulai ulang bot
Catatan: file .env.local dibaca otomatis dari folder aplikasi (oleh Next.js & script bot), jadi tidak ada konfigurasi tambahan untuk variabel lingkungan.

B Opsi B — Docker (pengganti PM2)

Docker membungkus aplikasi beserta seluruh kebutuhannya ke dalam "kotak" (container) yang identik di mana pun dijalankan. Sangat rapi dan portabel — kalau suatu hari pindah server, tinggal jalankan perintah yang sama. File Dockerfile & docker-compose.yml sudah saya siapkan di kode Anda.

Peringatan: pakai satu cara saja. Jika sudah memakai PM2 atau systemd, berhentikan dulu sebelum menjalankan Docker.
B.1 Install Docker (sekali saja)
Di VPScurl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
newgrp docker

Logout & login SSH sekali jika docker tidak dikenali.

B.2 Buat file .env untuk nilai saat build

Next.js menanamkan nilai NEXT_PUBLIC_* ke dalam aplikasi saat build. Buat file .env di folder aplikasi (di samping docker-compose.yml): 

Di VPSnano .env

Isi (salin 3 baris ini dari .env.local Anda, ganti domain):

Isi file .envNEXT_PUBLIC_APP_URL=https://ytc-web.com
NEXT_PUBLIC_SUPABASE_URL=https://rbbvsrzaanmgdfbesfng.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...panjang...

Simpan: Ctrl+O → Enter → Ctrl+X. (File .env.local juga tetap dibutuhkan — dipakai saat runtime via env_file.)

B.3 Bangun & jalankan
Di VPSdocker compose up -d --build

Ini membangun image lalu menjalankan 2 service: web (port 3000) dan telegram (bot).

Di VPSdocker compose ps                # status container
docker compose logs -f web       # log aplikasi (keluar: Ctrl+C)
docker compose logs -f telegram  # log bot
B.4 Perintah sehari-hari
Di VPSdocker compose restart web          # mulai ulang web
docker compose stop                  # hentikan semua
docker compose start                 # nyalakan lagi
docker compose down                  # hentikan & hapus container (data aman)
B.5 Update aplikasi (setelah ada perubahan kode)
Di VPSgit pull
docker compose up -d --build
Catatan penting: kalau NEXT_PUBLIC_APP_URL di .env berubah, aplikasi harus di-build ulang (docker compose up -d --build) karena nilainya sudah tertanam di dalam aplikasi. Nginx tetap mengarah ke http://127.0.0.1:3000 seperti biasa.

7 Nginx + HTTPS (kunci gembok)

Kenapa wajib? Tanpa HTTPS (alamat berawalan https://):
  • Browser bisa memblokir beberapa fitur (clipboard, popup pembayaran).
  • Webhook pembayaran Midtrans dan webhook Telegram tidak akan diterima (mereka hanya mengirim ke URL https://).
  • Data pengunjung tidak terenkripsi.
7.1 Arahkan domain ke VPS

Di pengelola DNS domain Anda (tempat membeli domain), buat 2 record A:

NamaTipeNilai
@ (root)AIP VPS Anda
wwwAIP VPS Anda
7.2 Buat konfigurasi Nginx
Di VPSsudo nano /etc/nginx/sites-available/ytc-web

Isi (ganti ytc-web.com dengan domain Anda):

Isi fileserver {
    listen 80;
    server_name ytc-web.com www.ytc-web.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Aktifkan:

Di VPSsudo ln -s /etc/nginx/sites-available/ytc-web /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

nginx -t harus menampilkan syntax is ok.

7.3 Pasang SSL otomatis (Certbot)
Di VPSsudo certbot --nginx -d ytc-web.com -d www.ytc-web.com

Ikuti pertanyaan (untuk email isi alamat Anda, setuju persyaratan). Setelah selesai, Nginx otomatis diarahkan ke HTTPS. Perbarui juga NEXT_PUBLIC_APP_URL di .env.local menjadi https://ytc-web.com, lalu pm2 restart ytc-web.

Sertifikat otomatis diperpanjang oleh Certbot — tidak perlu urus lagi. Cek dengan sudo systemctl status certbot.timer.

8 Bot Telegram

Notifikasi pesanan/cashback dan perintah /listo, /listcb, /help sudah berfungsi lewat script polling. Di VPS, cukup pastikan dua hal:

  • TELEGRAM_BOT_TOKEN & TELEGRAM_CHAT_ID sudah ada di .env.local (langkah 5.2) — script PM2 ytc-telegram otomatis membacanya.
  • Proses ytc-telegram berstatus online di pm2 status.

Kalau nanti sudah pakai HTTPS, Anda bisa beralih ke webhook (Telegram mengirim pesan langsung ke server, tanpa script polling). Tapi ini tidak wajib — polling via PM2 seperti sekarang sudah baik dan lebih sederhana.

Penting: jangan aktifkan polling dan webhook bersamaan — salah satu akan error. Pakai salah satu saja.
Pindah dari Vercel ke VPS? Jika di Vercel bot memakai webhook, lakukan ini sekali sebelum mematikan Vercel: curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook". Setelah itu polling di VPS (proses ytc-telegram) otomatis jalan. Pakai .env.local dengan nilai yang sama — hanya NEXT_PUBLIC_APP_URL diganti domain VPS sebelum build.

9 Pengingat otomatis cashback (opsional)

Route pengingat sudah disiapkan di file app/api/cron/telegram-digest/route.ts namun sengaja di-matikan (isi di-comment). Kalau Anda ingin pengingat harian "ada klaim yang sudah ≥5 hari harus segera dicairkan":

  1. Buka file app/api/cron/telegram-digest/route.ts, hapus semua komentar pada bagian logika (lihat petunjuk di dalam file).
  2. Tambahkan CRON_SECRET=string-acak-panjang di .env.local.
  3. Build ulang & restart: npm run build lalu pm2 restart ytc-web.
  4. Jadwalkan lewat cron server (dijalankan setiap hari pukul 09.00 WIB = 02.00 UTC): 
    Di VPScrontab -e

    Tambahkan baris (ganti domain):

    Isi crontab0 2 * * * curl -s -X GET https://ytc-web.com/api/cron/telegram-digest
Catatan: jika tidak butuh pengingat otomatis, biarkan file tersebut apa adanya (route nonaktif). Perintah manual /listcb tetap bisa Anda pakai kapan saja.

10 Keamanan & backup

Keamanan

  • Password admin (web) kuat & berbeda — ubah di .env.local.
  • SUPABASE_SERVICE_ROLE_KEY jangan pernah bocor (tidak boleh tampil di kode depan browser).
  • File .env.local tidak boleh ikut di-upload ke repo publik — tambahkan ke .gitignore.
  • Firewall ufw aktif (hanya 22, 80, 443).
  • Log & pantau aplikasi lewat pm2 logs.

Backup

  • Database (paling penting): data pesanan & klaim tersimpan di Supabase (di luar VPS). Aktifkan backup otomatis di dashboard Supabase (Project Settings → Backups), atau unduh manual via SQL Editor.
  • File installer: sudah di Cloudflare R2 (di luar VPS) — aman.
  • Kode aplikasi: simpan di GitHub (repo privat) — salinan ekstra di luar VPS.
  • Env: simpan salinan .env.local di tempat aman (mis. password manager).

Pemeliharaan rutin (bulanan)

Di VPSsudo apt update
sudo apt upgrade -y
sudo reboot

Setelah reboot, PM2 otomatis menghidupkan aplikasi (karena pm2 startup).

11 Checklist go-live

Centang sebelum website dinyatakan live:

  • VPS menyala, spek sesuai, swap aktif (jika RAM 1 GB).
  • Node.js 20, Nginx, Certbot, PM2, Git terpasang.
  • Kode terpasang, npm run build berhasil.
  • .env.local lengkap; NEXT_PUBLIC_APP_URL memakai domain; password admin & secret diganti.
  • PM2: ytc-web dan ytc-telegram online; pm2 save & pm2 startup dijalankan.
  • Domain mengarah ke IP VPS; Nginx & Certbot terpasang → situs bisa dibuka via https://domain.
  • Uji beli (mode manual): pesanan masuk → notif Telegram /listo → status berubah di admin.
  • Uji klaim cashback: notif Telegram /listcb muncul.
  • Firewall aktif; tidak ada port tak perlu.
  • Backup database Supabase sudah diaktifkan.

Saat Midtrans nanti disetujui (langkah lanjutan)

  • Aktifkan integrasi Midtrans (isi MIDTRANS_SERVER_KEY, NEXT_PUBLIC_MIDTRANS_CLIENT_KEY, MIDTRANS_IS_PRODUCTION=true).
  • Atur Notification URL di dashboard Midtrans → https://domain/api/midtrans-webhook (URL Anda sudah https, syarat terpenuhi).
  • Tambahkan biaya admin per metode (sesuai ketentuan Midtrans) & checkbox persetujuan Payment Gateway.
